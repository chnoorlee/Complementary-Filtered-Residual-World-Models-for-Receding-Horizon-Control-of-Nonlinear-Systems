# Reproducibility commands

The source tree separates literature retrieval, controlled-system simulation,
window construction, model training, frozen confirmation, statistical analysis,
and artifact auditing. Experimental values are generated from model outputs;
none is hand-entered into a result file.

## Verified local runtime

The checked runtime is `.conda_env` with Python 3.11.15 and PyTorch
2.11.0+cu130. The confirmation uses CUDA when available and otherwise fails
over to CPU. In PowerShell, expose the source package before module commands:

```powershell
$env:PYTHONPATH = "code"
```

## Literature retrieval and verification

```powershell
& '.\.conda_env\python.exe' code\literature_retrieval.py --output-dir literature --per-query 25
& '.\.conda_env\python.exe' code\screen_literature.py
& '.\.conda_env\python.exe' code\make_bibliography.py
& '.\.conda_env\python.exe' code\audit_citations.py
```

The network-backed commands are for refreshing the corpus. The manuscript must
not be rebuilt from an unaudited refresh. `make_bibliography.py` fails unless
the shortlist and targeted supplement are covered exactly by verified rows in
`literature/citation_audit.json`; it writes
`literature/bibliography_manifest.json` to bind those sources to the generated
41-entry bibliography.

## Immutable v3 confirmation

The generic `rgpwm.experiment` command is development-only and rejects the
frozen seeds and reserved output directory. Confirmation has one no-override
training command and one versioned, no-override analysis command:

```powershell
$env:PYTHONPATH = "code"
& '.\.conda_env\python.exe' -m rgpwm.confirm_run
& '.\.conda_env\python.exe' -m rgpwm.confirm_analyze_amended
```

The first command validates `docs/12_cfr_confirmatory_contract.json`, source
hashes, and the tuning archive before generating data. It writes one JSON and
one checkpoint per method--seed--system condition and resumes only an exact,
paired, provenance-matched subset. The original frozen analysis entry point is
retained for provenance; its first invocation stopped before any inference
because the generic loader did not propagate the top-level descriptive
`parameter_count`. The separately hashed amendment in
`docs/14_cfr_analysis_amendment.json` fixes only that schema join. Its command
refuses partial grids and existing outputs, validates all 440 JSON/PT pairs,
1,320 aggregate cells, 126,720 trajectory rows, data hashes, and trajectory
pairing, and then calls the unchanged frozen statistical implementation.

After locked analysis, manuscript assets are generated by:

```powershell
& '.\.conda_env\python.exe' code\make_confirmatory_manuscript_assets.py
& '.\.conda_env\python.exe' code\build_springer_submission.py
```

The second command expands all section and generated-table inputs into
`paper/mypaper/main_springer.tex`, as required by the official Springer Nature
single-file template. It intentionally fails while any locked result asset or
verified bibliography input is missing or stale. It also writes
`paper/submission_source_manifest.json`, which binds every used manuscript
section, the bibliography, result-asset manifest, bibliography manifest,
builder source, and flattened output by SHA-256. Author, affiliation, funding,
contribution, and repository metadata remain explicit placeholders for the
submitting authors.

## Measured-flight external extension

The NanoDrone extension is recorded separately in
`plans/26_external_validity_revision.md`; it does not modify the original
synthetic H1/H2 analysis. Download the author-released records from the pinned
source commit using `external_validity.data.download_dataset` if they are not
already present. Each record is verified against its upstream Git LFS hash.
The downloaded data have no redistribution license identified in the pinned
repository; the package records their source URLs and hashes rather than
granting a license to upstream records.

```powershell
$env:PYTHONPATH = "code"
& '.\.conda_env\python.exe' -c "from external_validity.data import download_dataset; download_dataset('data/external/nanodrone')"
& '.\.conda_env\python.exe' -m external_validity.run pilot
& '.\.conda_env\python.exe' -m external_validity.run train
# Only for an interrupted, source-matched, incomplete training grid:
& '.\.conda_env\python.exe' -m external_validity.run resume
# Evaluate only after all validation selection and final training finish:
& '.\.conda_env\python.exe' -m external_validity.run evaluate
& '.\.conda_env\python.exe' code\make_external_assets.py
& '.\.conda_env\python.exe' code\build_springer_submission.py
```

The external runner uses complete-flight train/validation/test splits and
training-only scales and thrust fitting. It evaluates 25- and 50-step
predictions under four context conditions. Its normalized RMSE is the square
root of mean squared error across windows, steps, and coordinates within each
flight. Scores are then averaged equally across three flights, followed by
mean/sample SD across five training seeds. This metric differs from the frozen
synthetic metric, which averages per-coordinate normalized RMSEs. Training
seeds describe optimization variability, not independent platforms.

The external asset generator verifies the full prediction/checkpoint/source
chain, recomputes recorded errors, and rejects incomplete or inconsistent
grids. Its separate manifest binds every external table, figure, and result
macro. The submission builder validates this chain and the independently
verified NanoDrone citation in `literature/external_citation_audit.json`, while
retaining the original 41-entry bibliography and synthetic asset checks.

## Manuscript build

MiKTeX on the verified machine lacks the Perl engine required by `latexmk`.
From `paper\mypaper`, use the equivalent explicit chain:

```powershell
pdflatex -interaction=nonstopmode -halt-on-error main.tex
bibtex main
pdflatex -interaction=nonstopmode -halt-on-error main.tex
pdflatex -interaction=nonstopmode -halt-on-error main.tex
```

The final PDF is valid only when the locked confirmatory analysis exists and
the generated result macros and tables have been refreshed from it.

For `main_springer.tex`, expose the official December 2024 template and
bibliography-style directories during compilation:

```powershell
$env:TEXINPUTS = "..\springer-official\sn-article-template;"
$env:BSTINPUTS = "..\springer-official\sn-article-template\bst;"
pdflatex -interaction=nonstopmode -halt-on-error main_springer.tex
bibtex main_springer
pdflatex -interaction=nonstopmode -halt-on-error main_springer.tex
pdflatex -interaction=nonstopmode -halt-on-error main_springer.tex
```

After the final successful chain, validate the log and bind the PDF, BBL,
template class, bibliography style, build recipe, generator, source manifest,
and local tool versions into a separate build manifest:

```powershell
& '..\..\.conda_env\python.exe' ..\..\code\create_springer_build_manifest.py
```
